\begin{center}
    {\LARGE \textbf{\textcolor{skitnavy}{ABSTRACT}}}
\end{center}
\vspace{1cm}

Preparing for technical software engineering interviews in the modern era presents significant challenges for students and aspiring developers. Traditional study methods are often fragmented across disparate platforms, suffer from outdated static content, lack structured model explanations, and provide zero administrative visibility into candidate learning deficits. 

This project presents \textbf{OmniFAQ AI}, an intelligent, full-stack tech interview preparation web platform that unifies high-quality curated technical interview repositories with real-time generative capabilities powered by \textbf{Google Gemini Generative Artificial Intelligence}. Developed using a three-tier client-server architecture, the system incorporates an ultra-responsive, single-page application (SPA) frontend designed with modern glassmorphism aesthetics, backed by a modular \textbf{PHP 8.2 REST API} router and a high-performance relational database engine.

A pivotal innovation of the platform is its \textbf{dual-driver database persistence architecture}, which dynamically binds to cloud-hosted MySQL/MariaDB instances when reachable, while offering automatic, zero-configuration failover to an embedded SQLite engine equipped with self-seeding mechanisms. Furthermore, the platform introduces an \textbf{automated self-learning loop}: when candidates query emerging or un-indexed technical topics, the backend triggers Google Gemini Generative API under strict JSON schema constraints. The synthesized questions, comprehensive model answers, taxonomic categories, and difficulty tiers are simultaneously delivered to the user and persisted into the database, transforming transient AI inferences into permanent knowledge assets without redundant API overhead.

In addition, the system incorporates a client-side practice evaluation engine measuring conceptual keyword coverage, role-based access control secured by Bcrypt cryptographic hashing, and a comprehensive administrative telemetry dashboard tracking search volume, query resolution percentage, and unresolved student inquiries. The platform has been containerized using \textbf{Docker} and successfully deployed on the \textbf{Render} cloud platform, demonstrating high reliability, sub-second latency, and horizontal scalability.

\vspace{1cm}
\textbf{Keywords:} Technical Interview Preparation, Generative AI, Google Gemini API, PHP 8 REST API, Dual-Driver Database Architecture, SQLite/MySQL, Glassmorphism UI, Docker Containerization, EdTech.

\chapter{Introduction}
\label{chap:intro}

\section{Project Overview}
In today's highly competitive software development industry, technical recruitment processes evaluate candidates across diverse domains including core language mechanics, modern frontend libraries, backend distributed systems, relational databases, and enterprise architectural design. Engineering students and job seekers routinely face multi-stage technical interviews requiring rigorous theoretical understanding, rapid problem-solving skills, and the ability to articulate structured, in-depth architectural solutions.

\textbf{OmniFAQ AI} is a comprehensive, modern web-based technical interview training platform engineered to streamline and elevate candidate preparation. Built upon a decoupled client-server architecture, the platform bridges the gap between static study material and dynamic, real-world candidate needs by pairing a rich, pre-loaded repository of domain-specific interview questions with the real-time synthesis power of \textbf{Google Gemini Generative AI}. The application enables learners to search, filter by adaptive difficulty levels (Easy, Medium, Hard), practice conceptual answers with automated keyword feedback, and dynamically expand the platform's repository on-demand.

\section{Motivation and Background}
With the rapid evolution of modern web frameworks, cloud technologies, and developer tooling, software engineering curricula frequently lag behind current industry interview expectations. Candidates typically spend hundreds of hours navigating dozens of disconnected resources, including competitive coding repositories, community forums, medium articles, and fragmented documentation. 

Furthermore, existing question-and-answer repositories are inherently static: if a student is interviewing for a niche framework (e.g., GraphQL, Docker, Kubernetes, WebSockets) that has not been explicitly cataloged by the site administrator, the user receives zero guidance. Recent advancements in Large Language Models (LLMs), particularly Google's Gemini family of generative models, present a transformative opportunity to convert static educational portals into self-learning, adaptive environments capable of generating domain-accurate interview questions and gold-standard model answers on the fly.

\section{Problem Statement}
Contemporary technical interview preparation suffers from four foundational bottlenecks:
\begin{enumerate}
    \item \textbf{Fragmentation of Learning Resources:} Candidates are forced to bounce between competitive programming websites, blogs, and community forums without a unified repository covering theory, architectural questions, and code semantics.
    \item \textbf{Lack of Comprehensive Model Explanations:} Many portals supply interview questions without high-scoring, structured technical answers that demonstrate depth of understanding.
    \item \textbf{Static, Non-Adaptive Repositories:} Conventional FAQ systems cannot adapt dynamically when learners query emerging, modern, or specialized developer topics.
    \item \textbf{Zero Telemetry on Student Knowledge Gaps:} Educators and platform administrators lack empirical data regarding which topics students search for most frequently and where learners encounter unresolved queries.
\end{enumerate}

\section{Objectives of the System}
The primary objectives of the OmniFAQ AI project are as follows:
\begin{itemize}
    \item \textbf{Unified Multi-Domain Question Bank:} To engineer a curated repository covering five core technical disciplines: JavaScript, React, Node.js, SQL, and System Design.
    \item \textbf{On-Demand Generative AI Expansion:} To integrate the Google Gemini API to dynamically generate 3--4 rigorous interview questions with model answers whenever an unresolved topic is searched.
    \item \textbf{Self-Learning Database Persistence:} To implement an automated ingestion pipeline where AI-generated questions are sanitized and permanently written into the database, benefiting all future platform visitors without recurring API costs.
    \item \textbf{Debounced Real-Time Search Engine:} To create a fast, client-side debounced search interface with weighted relevance scoring across question titles, keyword tags, and model answers.
    \item \textbf{Interactive Candidate Practice Engine:} To supply an active recall practice module that analyzes a user's typed response against expected technical keywords and provides real-time coverage scores.
    \item \textbf{Administrative Analytics and Gap Detection:} To build an administrative telemetry dashboard that logs all user searches, computes resolution rates, and surfaces high-priority unresolved queries for curriculum refinement.
    \item \textbf{Robust Dual-Driver Database Deployment:} To design an environment-agnostic backend supporting cloud MySQL as well as automatic, zero-configuration failover to an embedded SQLite engine.
\end{itemize}

\section{Project Scope}
The scope of OmniFAQ AI encompasses full-stack software development, REST API design, cryptographic security, database normalization, prompt engineering, containerization, and cloud deployment. It addresses Computer Science undergraduate students, bootcamp graduates, junior-to-mid level software engineers, technical mentors, and academic institutions. Complete protection against SQL Injection is guaranteed via PDO parameterized queries, secure user authentication with Bcrypt password hashing, and role-based access control.

\section{Frontend Technology Stack}
The presentation tier of OmniFAQ AI is engineered as an ultra-responsive Single Page Application (SPA) designed to run seamlessly across all devices.

\subsection{HTML5 and CSS3 Custom Glassmorphism}
The user interface leverages modern CSS3 properties, including CSS Custom Properties, Flexbox, CSS Grid, and \texttt{backdrop-filter: blur(20px)} for high-contrast glassmorphic aesthetics. A dark-slate teal color scheme (\#112F3B) with glowing cyan accents (\#0891B2, \#06B6D4) provides visual comfort during extended study sessions. The entire core stylesheet is inlined into the primary markup, eliminating render-blocking waterfalls and preventing unstyled layout shifts (FOUC).

\subsection{jQuery 3.7.1 and DOM Event Architecture}
jQuery is employed to handle client-side view routing, form serialization, debounced asynchronous HTTP queries, accordion-style answer reveals, and dynamic DOM injection of question cards without necessitating bulky virtual DOM frameworks.

\subsection{Lucide Modern Vector Icons}
Lucide Icons are utilized across headers, difficulty badges, input adornments, and action buttons, providing crisp SVG visuals with near-zero runtime footprint.

\section{Backend Architecture: PHP 8.2 REST API}
The business logic tier is powered by PHP 8.2, chosen for its mature ecosystem, high execution speed, robust native standard library, and exceptional deployment portability.

\subsection{RESTful Router Pattern}
Rather than scattering logic across numerous detached script files, backend communication is channeled through a centralized API controller (\texttt{api.php}). The router parses incoming HTTP requests, enforces CORS headers, validates user roles, dispatches execution to designated handler functions, and emits standardized JSON responses.

\subsection{Database Abstraction with PDO}
All database interactions are conducted via the PHP Data Objects (PDO) extension utilizing a thread-safe Singleton connection handler. Prepared statements with explicit parameter binding are utilized exclusively, eliminating SQL injection attack vectors.

\section{Database Architecture: Dual-Driver Engine}
A distinguishing architectural achievement of OmniFAQ AI is its resilient dual-driver database abstraction implemented in \texttt{db.php}:
\begin{enumerate}
    \item \textbf{MySQL / MariaDB Cloud Engine:} If environment variables (\texttt{DB\_HOST}, \texttt{DB\_USER}, etc.) are detected, the backend connects to an enterprise MySQL instance utilizing InnoDB storage engines and UTF-8 mb4 encoding for full-text search indexing.
    \item \textbf{Zero-Config SQLite Embedded Engine:} If no remote database is configured (or if MySQL connectivity times out), the system gracefully falls back to an embedded SQLite3 database (\texttt{database.sqlite}). On initial launch, the system automatically executes schema definitions and seeds eighteen expert technical interview questions and default administrator accounts.
\end{enumerate}

\section{Artificial Intelligence Integration: Google Gemini API}
For on-demand question synthesis, OmniFAQ AI interfaces with the \textbf{Google Gemini API} (\texttt{gemini-2.5-flash}). Gemini was selected for its high processing speed, state-of-the-art technical reasoning, and support for native structured JSON outputs (\texttt{responseMimeType: "application/json"}). Requests are transmitted via backend cURL routines, shielding the client browser from exposing API keys.

\section{Containerization and Cloud Deployment}
The application is fully containerized using an official \texttt{php:8.2-apache} base image. A dynamically evaluated entrypoint command substitutes Apache's listening port at container startup (\texttt{sed -i 's/Listen [0-9]*/Listen \$\{PORT:-80\}/'}), making the container compliant with cloud environments such as \textbf{Render} and \textbf{Railway} that allocate arbitrary port numbers dynamically.

\chapter{Implementation and Key Features}
\label{chap:impl}

\section{Debounced Real-Time Search and Weighted Ranking}
To achieve instantaneous search without flooding the server with network requests, the client-side search box implements a 400-millisecond debounce mechanism.

\begin{lstlisting}[language=JavaScript, caption={Client-Side Search Debouncing Implementation}]
$('#search-input').on('input', function() {
    clearTimeout(searchDebounceTimer);
    const query = $(this).val().trim();
    if (query.length === 0) {
        resetDashboardSearch();
        return;
    }
    searchDebounceTimer = setTimeout(function() {
        executeSearch(query);
    }, 400); // 400ms debounce interval
});
\end{lstlisting}

Incoming queries are tokenized, stripped of English stop words, and evaluated through a dynamic weighted SQL relevance formula:
\begin{equation}
\text{Relevance Score} = \sum_{w \in \text{Keywords}} \left( 4 \cdot \mathbb{I}_{\text{question}}(w) + 3 \cdot \mathbb{I}_{\text{tags}}(w) + 1 \cdot \mathbb{I}_{\text{answer}}(w) \right)
\label{eq:scoring}
\end{equation}

\section{On-Demand Generative AI Pipeline}
When a user searches for an uncataloged technology (e.g., ``Docker'' or ``Kubernetes''), the system displays an interactive ``Generate Live AI Questions'' action. Upon trigger, the backend dispatches an engineering prompt enforcing strict JSON output to Google Gemini API (\texttt{gemini-2.5-flash}). The synthesized questions are automatically inserted into the database using prepared statements and displayed to the user.

\section{Interactive Practice and Keyword Evaluation Engine}
Candidates can enter their own answers in an interactive practice area. The system evaluates the candidate's response against expected technical concept keywords and computes an objective coverage score:
\begin{equation}
\text{Coverage Score} = \left( \frac{|\text{Matched Key Concepts}|}{|\text{Expected Key Concepts}|} \right) \times 100\%
\end{equation}

\section{Role-Based Access Control and Cryptographic Security}
Passwords are never stored in plaintext; they are hashed using salted Bcrypt via PHP's \texttt{password\_hash(\$password, PASSWORD\_DEFAULT)} and verified via \texttt{password\_verify()}. Role claims segregate standard learners from administrators.

\section{Administrative Telemetry and Knowledge Gap Analysis}
The platform logs every search transaction within the \texttt{search\_analytics} table. The administrative control center computes real-time operational indicators:
\begin{equation}
\text{Resolution Rate} = \left( \frac{\text{Total Searches} - \text{Unresolved Searches}}{\text{Total Searches}} \right) \times 100\%
\end{equation}
